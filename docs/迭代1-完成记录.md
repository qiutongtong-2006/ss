# 迭代 1 完成记录：学生注册登录与提交报修

日期：2026-10-20 至 2026-10-21

## 一、迭代目标

学生能用学号注册并登录，登录后提交一条带照片的报修，提交成功后生成唯一工单号，工单状态为“待受理”。

## 三、实现内容

### M1 注册与登录

- 学生注册页，用户名即学号
- 注册角色由后端固定为 `student`
- 重复学号校验、两次密码校验和 Django 密码强度校验
- 注册成功后自动登录
- 登录、退出和按角色进入首页
- 未登录访问首页或提交报修页时跳转登录页

### M2 提交报修

- 楼栋支持自由输入，不限制楼栋数量
- 楼栋名称自动规范化：二号楼、2栋、2幢、2号宿舍楼统一为 2号楼
- 宿舍号、维修地址、联系电话、报修分类和故障描述
- 联系电话默认带出注册资料中的号码，允许本次修改
- 现场照片选填，可上传 0～3 张；如上传，单张不超过 5 MB
- 图片即时预览
- 选填备注
- 入室授权复选框，默认不勾选
- 未授权时，详情页提示宿管先联系学生约定时间
- 工单号自动生成，格式为 `BX + 日期 + 四位序号`
- 新工单状态为“待受理”

### 页面优化

- 浅蓝色柔和渐变背景
- 柔和的导航栏、卡片边框与阴影
- 登录和注册页左右分栏
- 学生首页快捷入口卡片
- 报修表单按区块组织
- 工单详情页处理进度条、信息卡片和照片画廊

## 六、设计决定

1. **Django 使用 5.2 LTS**：本机 MySQL 为 8.0.45，Django 6.1 要求 MySQL 8.4 以上，因此固定使用 5.2 LTS。
2. **楼栋自由输入但统一写法**：兼顾楼栋数量不设上限和后续筛选统计的数据质量。
3. **入室授权默认不勾选**：涉及宿舍隐私和财产安全，采用明确授权，而不是默认同意。
4. **联系发生在系统外**：本项目不集成短信和微信推送，宿管通过工单中的联系电话联系学生，后续在迭代 2 记录联系结果。
5. **现场照片选填但推荐上传**：不因缺少照片阻塞报修提交，但照片仍作为辅助维修判断的重要信息保留。
