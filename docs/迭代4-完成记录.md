## 三、实现内容

### 数据基础

- 新增 `Evaluation` 模型，与工单一对一关联
- 评价保存学生、1～5 星评分、评价内容和评价时间
- `WorkOrder` 增加 `return_count`，记录退回返修次数
- 新增迁移 `0009_workorder_return_count_evaluation`
- 工单删除受后台只读约束保护，前台也不提供删除入口

### 验收与评价

- 新增 `/repair/<工单ID>/acceptance/` 验收评价页
- 只有报修学生本人可以打开和提交
- 只有“待验收”工单可以验收
- 评分必须是 1～5 星，评价内容必填
- 评分控件使用金色五角星交互，悬停预览、点击点亮，并显示对应满意度提示
- 验收成功后工单变为“已完成”，记录验收时间
- 同一工单的评价由数据库唯一约束保证只有一条
- 详情页展示星级、评分和评价内容

### 退回返修

- 新增 `/repair/<工单ID>/return/` 退回页
- 只有报修学生本人可以退回
- 退回原因必填，并写入状态日志
- 状态由“待验收”回到“维修中”，由原维修人员继续返修
- 退回次数加一，之前的维修记录全部保留
- 返修完工后可再次验收，最终只生成一条评价

### 工单详情时间线

- 处理日志按时间顺序展示提交、受理派单、接单、完工、退回和验收
- 时间线显示完整年月日与时间
- 多次返修记录和最终评价同时保留
- 处理信息中增加验收时间与退回返修次数
- 学生首页与工单详情操作区提供验收和退回入口

## 四、权限与异常处理

| 操作 | 处理 |
| --- | --- |
| 其他学生访问验收或退回页 | 403 |
| 维修人员、宿管访问验收或退回页 | 403 |
| 未登录访问验收或退回页 | 跳转登录 |
| 非“待验收”工单验收或退回 | 拦截并保持原状态 |
| 评分为空或不在 1～5 范围 | 表单校验失败 |
| 评价内容或退回原因为空 | 表单校验失败 |
| 重复提交验收 | 只保留一条评价和一条验收日志 |
| 同一工单创建第二条评价 | 数据库唯一约束拒绝 |
| 退回后未重新完工直接验收 | 被状态校验拦截 |
| 并发状态变化 | 事务内锁定工单并重新检查状态 |
