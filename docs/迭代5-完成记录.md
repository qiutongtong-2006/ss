## 三、三角色权限加固

### 统一权限策略

- 新增 `repair/permissions.py`，统一处理登录、角色和工单数据范围。
- `role_required` 对未登录用户保留跳转登录页的行为。
- 已登录但角色不符时统一返回 403，不再通过页面跳转掩盖越权请求。
- 工单详情使用统一的可见性策略：学生仅本人、维修人员仅本人被派单、宿管和超级管理员可查看全部。
- 学生本人和维修人员本人操作继续做对象级校验，防止仅靠修改工单 ID 越权。

### 功能边界

| 功能 | 学生 | 维修人员 | 宿管 / 超级管理员 |
| --- | --- | --- | --- |
| 学生首页、提交报修、我的报修 | 可用 | 403 | 403 |
| 维修任务列表、接单、提交完工 | 403 | 仅本人被派工单 | 403 |
| 工单池、受理、驳回 | 403 | 403 | 可用 |
| 查看工单详情 | 仅本人报修 | 仅本人被派工单 | 全部 |
| 撤销、验收、退回、评价 | 仅本人且状态允许 | 403 | 403 |

### 特殊规则

- 超级管理员可以进入宿管功能并维护后台数据，但不能冒充学生验收或维修人员完工。
- 未知角色无法通过工单详情兜底校验。
- 学生自助注册只生成学生角色，请求中伪造 `role`、`is_staff` 或 `is_superuser` 均无效。
- 越权请求在状态校验和数据写入前被拒绝，不产生状态日志、维修记录或评价。

## 四、基础数据维护

### Admin 维护

- 楼栋和报修分类支持在 Django Admin 新增、修改、启用和停用。
- 列表直接展示关联工单数量，并支持在列表中切换启用状态。
- 被工单引用的楼栋或分类不提供删除权限，数据库外键同时使用 `PROTECT` 兜底。
- 未被引用的基础数据仍可在后台正常删除。
- 非后台员工身份的普通宿管不能进入 Django Admin。

### 报修提交

- 学生提交报修时，楼栋由文本输入改为下拉选择。
- 楼栋和分类只显示 `is_active=True` 的数据。
- 学生不能在提交报修时自行创建楼栋，基础数据统一由 Admin 维护。
- 停用的楼栋和分类不出现在新报修选项中，但仍保留在历史工单和筛选条件中。
