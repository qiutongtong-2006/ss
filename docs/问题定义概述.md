# 问题定义概述

项目名称：学生宿舍报修管理系统

分析员单位：××大学计算机与人工智能学院（个人独立开发）

负责人：×××（本人）

用户单位：××大学后勤管理处 学生宿舍管理科

问题概述：学生宿舍设施报修目前依靠口头告知、电话联系或楼栋微信群留言，信息零散且无统一记录，宿管依靠纸质登记或聊天记录转达维修人员，容易出现信息遗漏、重复报修和进度无法查询的情况；学生提交报修后得不到回执，不知道由谁处理、何时上门；后勤部门也缺少完整数据来统计故障分布和维修工作量。本项目拟建立一个面向学生、维修人员和宿管三类用户的学生宿舍报修管理系统，把报修信息结构化、处理过程状态化、处理结果数据化：学生在线提交报修并查看进度，宿管集中受理派单，维修人员接单并记录维修过程，最后由学生验收评价，形成"报修—派单—维修—验收—归档"的在线闭环。

项目规模：约 20 个工作日（3～4 周，每周投入约 20 小时），约 2000 行代码、8 张数据表。系统采用 Python + Django + MySQL 开发，B/S 结构、服务端渲染、单机部署；无硬件采购，软件全部采用开源技术，直接开发费用接近于零。

可行性研究：建议进行 3 天，费用不超过 200 元，研究结论以书面材料的形式递交给用户单位，使其明白项目的必要性和可行性。
