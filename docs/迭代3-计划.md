# 迭代 3 计划：维修人员接单、记录与完工

日期：2026-10-23

## 一、迭代目标

维修人员可以查看派给自己的工单，完成接单、填写维修记录并提交完工。

## 二、本次承诺的用户故事

| 编号 | 用户故事 | 优先级 |
| --- | --- | --- |
| M4 | 维修人员查看派给自己的任务并接单 | Must |
| M5 | 维修人员填写维修记录并提交完工 | Must |
| M7 部分 | 保证“已派单 → 维修中 → 待验收”的合法流转 | Must |
| M8 部分 | 维修人员只能操作派给自己的工单 | Must |

## 三、验收标准

### 我的维修任务

1. 维修人员登录后可以进入“我的维修任务”。
2. 列表只显示派给当前维修人员的工单。
3. 任务列表支持按状态、楼栋、类别和关键词筛选。
4. 学生、宿管和其他角色不能进入维修任务列表。

### 接单

1. 只有状态为“已派单”且维修人员与当前用户一致的工单可以接单。
2. 接单后状态变为“维修中”，并记录开始维修时间。
3. 接单动作只接受 POST 请求，并写入状态日志“已派单 → 维修中”。
4. 其他维修人员直接请求接单地址返回 403。
5. 未处于“已派单”的工单不能接单，状态保持不变。

### 维修记录与完工

1. 只有接单后的“维修中”工单可以填写维修记录。
2. 维修内容必填，故障原因和更换材料选填。
3. 提交后保存维修记录、完工时间，并将状态变为“待验收”。
4. 状态日志记录“维修中 → 待验收”和维修摘要。
5. 未接单不能直接完工，其他维修人员不能提交完工。
6. 工单详情页展示维修记录、开始维修时间和完工时间。

## 五、本迭代不做

- 学生验收、退回和评分评价：迭代 4
- 维修人员完工照片：已取消，不纳入迭代 5
- 改派和超时提醒：后续增强

## 六、完成的定义

1. 维修人员能在浏览器中看到自己的任务并成功接单。
2. 维修人员能填写维修记录并提交完工。
3. 未派给自己的任务、未接单直接完工等越权或非法操作被拒绝。
4. 状态变化、操作人、时间和维修摘要写入状态日志。
5. 数据库迁移已生成并在 MySQL 应用。
6. 自动化测试和实际数据库端到端验证通过。
7. 迭代完成记录和 Git 提交完成。
