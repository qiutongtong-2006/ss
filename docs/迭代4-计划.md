# 迭代 4 计划：学生验收评价，主闭环打通

日期：2026-10-23

## 一、迭代目标

学生可以验收维修结果、退回返修并完成评分评价，工单主流程形成闭环。

| M6 | 学生确认修复或退回，确认后完成，退回后继续维修 | Must |

## 三、验收标准

### 验收通过与评价

1. 只有报修学生本人可以验收自己的“待验收”工单。
2. 验收页要求选择 1～5 星并填写评价内容。
3. 提交后工单变为“已完成”，记录验收时间。
4. 每个工单只能生成一条评价；重复提交不产生重复数据。
5. 其他学生、维修人员和宿管直接请求验收地址时被拒绝。

### 退回返修

1. 只有报修学生本人可以退回自己的“待验收”工单。
2. 退回必须填写原因；提交后工单回到“维修中”，由原维修人员继续返修。
3. 退回次数加一，返回原因写入状态日志，不生成评价。
4. 返修完工后可再次验收，最终评价仍只有一条。

### 工单时间线

1. 提交、受理派单、接单、完工、退回、最终验收按时间顺序展示。
2. 最终验收后展示评分、评价内容和评价时间。
3. 多次返修产生的维修记录与退回记录均保留。

## 五、本迭代不做

- 完工照片、统计报表和超时提醒：后续增强
- 宿管重新派单流程：按当前约定，退回后由原维修人员继续返修

## 六、完成的定义

1. 学生可在浏览器中完成验收评价或退回返修。
2. 越权访问、非法状态和重复提交均被安全拦截。
3. 评价唯一，状态日志与处理时间线完整。
4. 数据库迁移已生成并在 MySQL 应用。
5. 自动化测试和实际数据库端到端验证通过。
6. 迭代完成记录和 Git 提交完成。
