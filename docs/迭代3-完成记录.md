## 三、实现内容

### 数据基础

- `WorkOrder` 增加故障原因 `fault_cause`
- `WorkOrder` 增加维修内容 `repair_action`
- `WorkOrder` 增加更换材料 `materials_used`
- 迁移 `0006` 已生成并在 MySQL 应用
- 继续使用 `started_at` 和 `completed_at` 记录接单开始时间与完工时间

### 我的维修任务

- 新增 `/my-tasks/` 任务列表
- 只显示 `repairer` 为当前登录维修人员的工单
- 显示全部、待接单、维修中、待验收、已完成数量
- 支持按状态、楼栋、类别和关键词筛选
- 列表显示工单号、学生联系方式、位置、类别、状态和约定上门时间
- 维修人员首页和顶部导航已启用“我的维修任务”入口

### 接单

- 新增 `/repair/<工单ID>/start/`
- 只有工单对应维修人员可以接单
- 只允许“已派单 → 维修中”
- 接单后记录开始维修时间
- 自动写入一条“已派单 → 维修中”的状态日志
- 接口只接受 POST，防止通过普通链接修改状态

### 维修记录与提交完工

- 新增 `/repair/<工单ID>/complete/`
- 只有当前工单的维修人员在“维修中”状态可以提交
- 故障原因和更换材料选填，维修内容必填
- 提交后保存维修记录与完工时间
- 状态由“维修中”变为“待验收”
- 自动写入“维修中 → 待验收”的状态日志及维修摘要
- 工单详情展示维修记录、开始维修时间和完工时间

## 四、权限与异常处理

| 操作 | 处理 |
| --- | --- |
| 非维修人员访问我的维修任务 | 403 |
| 维修人员访问他人任务详情 | 403 |
| 其他维修人员尝试接单 | 403 |
| 其他维修人员尝试提交完工 | 403 |
| 非“已派单”工单接单 | 拦截并保持原状态 |
| 未接单直接提交完工 | 拦截并保持原状态 |
| 维修内容为空 | 表单校验失败，不改变状态 |
| 重复或并发提交 | 在事务内锁定并重新检查状态 |
